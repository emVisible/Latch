# Latch v3 方向

日期：2026-11-23  
地位：v2 已落地，见 [v2-loop.md](v2-loop.md)。本文只定下一版做什么，不在本阶段实现。

v2 把日常回路收成命令、路由和六份 skill：`daily` 先契约再地图，错误卡要过三题，`latched` 必须已经出现在某条路由的 `scope` 里。下一版不再加 skill，也不再加路由阶段。要补的是三件还没闩死的事。

## 1. 现场要能核对

现在的 `evidence:<dir>` 只认目录里已经有的文件。agent 可以先写文件再声称自己打开过 App。`on-site` 要求自己去点，但 Latch 检查的不是点击。

v3 的观察窗口收一份会话清单：谁打开了哪个目标、截屏或导出的 sha256、点中的位置。功能地图条目上的 `location` 和 `observe` 参加这次核对。对不上清单的回传，`claim.unresolved` 为真。未跟踪的新文件也算写入，空的 `writable` 照样拦住。

Latch 仍不自己去点。点击留在 agent 或人。Latch 只拒绝没有这次会话清单的结果。

## 2. 考卷和作者分开

现在的三题由写原子的同一次工作写成，`latch exam` 再拿原子去对夹具。结构要求挡得住抄三份一样的夹具，挡不住按原子的行为把题写圆。

v3 里，出题读取 `.latch/reads.json` 里的数据源，并且不读取这张卡的 `SKILL.md` 和原子实现。陷阱题对照一次已记录的天真改法，不再只对照作者填的 `naiveExpect`。作者批改自己的卷，退出码不算通过。

## 3. 闩住之后，下一次会停

`promote` 不会改 `route.json`。原子没进 scope 就不能标 `latched`，这只保证标签不撒谎。hook 默认跑的是 `daily`。一张卡的原子若只出现在别的路由里，下一次日常任务仍不会被它拦住。

v3 的 `latched` 还要求这个原子出现在 `daily` 实际会执行到的 scope 里。接进 `daily` 仍然是一次人审过的 diff，不由 promote 自动改路由。doctor 对「标了 latched、但 daily 走不到」报红。

租约现在在命令返回时释放。v3 把租约拉长到一次 hook 会话：同一 git 根上，会话没结束，第二个 agent 不能开始写。命令本身结束不再等于锁没了。

## 不做

- 不增加第六份以外的核心 skill，不把错误实例升成核心 skill。
- 不在上面三件有测试之前，给 openstrat 装 live hook。
- 不把控制台做成编辑器，不把点击运行时放进 Latch。
- 不改 Axis 的收藏库。
